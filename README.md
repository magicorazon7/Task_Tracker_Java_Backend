# Task Tracker Backend

Бэкенд-сервис для трекинга учебных задач.

## Требования

- Java 17+
- Maven
- Docker и Docker Compose
- Postman / Swagger / curl для вызова API (Желательно Swagger)
# Запуск приложения

## 1. Запустите базу данных в Docker:
```
docker-compose up -d
```
## 2. Сборка и запуск Spring Boot через Maven
```
mvn clean install
mvn spring-boot:run
```
После успешной сборки проекта адрес сервиса - http://localhost:8080/

# Swagger UI
Swagger UI доступен по адресу:
http://localhost:8080/swagger-ui/index.html#/
Через данный можно вызвать все эндопинты сервиса.

# Аутентификация
## 1. Регистрация пользователя
**_POST /api/auth/register_**

Пример тела:
```
{
  "email": "userClair@example.com",
  "password": "password123"
}
```
## 2. Авторизация (получение токена JWT)
Ниже приведен пример создания пользователя

**_POST /api/auth/login_**
```
{
  "email": "userClair@example.com",
  "password": "password123"
}
```
Ответ содержит токен:
```
{
  "token": "eyJhbGciOiJIUzI1..."
}
```
При работе в Swagger UI данный токен вставляется в 
"Authorize" (Сверху справа страницы, прим. **"Bearer" писать перед токеном не надо!**)
# 3. Роль - _Пользователь_
Пользователю доступны следующие эндопоинты для работы с трекером задач:
## Группы задач:
- **_GET /api/groups_** - список групп
- **_POST /api/groups_** - создать группу
- **_PUT /api/groups_** - редактировать группу
- **_DELETE /api/groups_** - удалить группу
## Задачи:
- **_GET /api/tasks_** - список задач
- **_POST /api/tasks_** - создать задачу
- **_PUT /api/tasks_** - редактировать задачу
- **_DELETE /api/tasks_** - удалить задачу
# 4. Роль - _Админ_
При первом запуске системы автоматически создаётся учётная запись администратора:
```
email: admin@example.com
password: admin123
```
Если администратор уже существует в базе данных — повторное создание не выполняется.
Для создания нового админстратора рекомендуется создать
пользователя и присвоить ему роль админа через
```
UPDATE users SET role = 'ADMIN' WHERE email = 'userClair@example.com';
```
## 4.1 Авторизация администратора
Администратор входит также через /api/auth/login и получает JWT-токен.
## 4.3 Возможности администратора
Администратор имеет доступ к отдельному API-разделу:
```
/api/admin/**
```
Администратор может выполнять:
### 1. Просмотр всех пользователей системы
**_GET /api/admin/users_**

Возвращает список зарегистрированных пользователей с их ролями
### 2. Просмотр всех задач выбранного пользователя
**_GET /api/admin/users/{userId}/tasks_**

Используется для просмотра задач конкретного пользователя
### 2. Просмотр всех групп
**_GET /api/admin/groups_**

Возвращает список всех созданных групп в системе
### 3. Просмотр агрегированной статистики по задачам
- **_GET /api/admin/statistics/status_** - количество задач по статусам
- **_GET /api/admin/statistics/groups_** - количество задач по группам
